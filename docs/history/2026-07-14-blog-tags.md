# Blog tags

## What shipped

Owner-curated tags for blog posts, surfaced primarily as **crawlable topic pages** for SEO, plus a browse-all hub and a per-page image story. Built via subagent-driven development (6 TDD tasks, each implementer + independent reviewer, then a whole-branch review), followed by two owner-requested extensions.

### Core feature (spec + plan + 6 tasks)
- **Data:** `tags` table (`name`, `slug`, `description`, `seo_title`, `seo_description`, `sort_order`, soft-deletes) + `blog_tag` pivot. **Blogs only** — a dedicated `Tag` model, not polymorphic and not `spatie/laravel-tags` (curated vocabulary, no on-the-fly sprawl). Slug uses a **partial unique index** (`WHERE deleted_at IS NULL`) so a soft-deleted tag's slug can be reused (mirrors the SpotGuide fix).
- **The single gate:** `Tag::scopeWithPublishedPosts()` is used by *every* public surface (tag bar, chips, tag-page existence, hub, sitemap) so empty / draft-only / soft-deleted-blog-only tags never appear or get advertised.
- **Tag page** `GET /blog/tags/{slug}` (`TagController@show`) — paginated published posts (12/page), 404 on unknown slug **and** on tags with no published posts (no thin indexable pages); per-tag `description` intro + SEO overrides with auto-generated fallbacks (`"Posts tagged {name} — Seabound Souls"`).
- **Surfaces:** a tag bar on `/blog`, tag chips on each post, both linking to the tag pages (internal linking is what makes the pages rank).
- **Admin:** owner-only `TagResource` (`/admin/blog-tags`, `TagPolicy` — contributors author guides, not blogs, so they never touch tags) + a `CheckboxList` on the blog form (assign from the curated list, no inline creation).
- **Sitemap:** tag pages added to `SitemapBuilder`.

### Extension 1 — hub + per-tag images (owner-requested mid-branch)
- **`GET /blog/tags` hub** (`TagController@index`) — a browse-all-topics page + crawlable SEO hub; tag cards with post counts. Routed **before** `/blog/{slug}` so the literal path isn't read as a blog slug; always resolves (empty state) so the bare path never 404s; added to the sitemap.
- **Two optional images per tag:** `thumbnail_media_id` (hub card) + `static_masthead_media_id` (tag-page hero), nullable FKs to `media_library`, set via admin MediaPickers.

### Extension 2 — gradient masthead is the site-wide default
- The designed **deep ocean-teal gradient hero** (layered radial glows + wave motif, pure CSS/SVG) was folded into `StaticMasthead`'s no-image branch, making it the default for **every** image-less page (blog, search, generic pages, homepage fallback, tag pages). Retired the interim `TagMasthead`.
- After a live look, tuned per owner feedback: a plain gradient fallback (no image, no centred-layout children) uses a **~55vh band** (not full-viewport — full-height felt too tall); photos and the SpotGuide centred/SpotOverview layout stay full-height.

## Findings worth keeping

- **`ensure_pages_exist` bites backend-first Inertia tests.** This repo has no `config/inertia.php`, so the package default `testing.ensure_pages_exist = true` applies — `assertInertia()->component('Blog/Tag')` fails if the `.tsx` doesn't exist yet. When asserting a component name before the page is built, pass the second arg: `->component('Blog/Tag', false)`. (Once the page exists the flag is redundant but harmless.)
- **Route ordering for the hub:** `/blog/tags` (2 segments) collides with `/blog/{slug}` (slug="tags") unless declared first. `/blog/tags/{slug}` (3 segments) can't collide, but the hub must precede `/blog/{slug}`. Regression-tested (a blog literally slugged "tags" must not shadow the hub).
- **`overflow-visible` masthead leaks blurred glows.** `StaticMasthead` is `overflow-visible` so the SpotGuide `SpotOverview` sidebar can extend past it — but that let the gradient's `blur-3xl` glows bleed into the content below. Fix: wrap the gradient layers in an inner `overflow-hidden` clip while keeping the outer container `overflow-visible`.
- **Centred title over the gradient needs its own contrast.** The SpotGuide centred title sits mid-hero where the bottom scrim is transparent; a no-masthead spot guide is admin-reachable, so a soft central radial vignette (children layout only) was added so the white title stays legible without dimming the corner glows.
- **App bundles pages eagerly** (`import.meta.glob(..., { eager: true })` in `app.tsx`) — there is no per-page code-split chunk, so "the build compiled cleanly" is the correct proof a new page component is valid, not "a `Blog/Tag` chunk was emitted".
- **Browser preview tooling was unresponsive both sessions** — verified functionally instead via HTTP + decoding the Inertia `data-page` JSON blob (component name + props). See the updated preview-verification memory. Pixel-level visual review remained an owner task.
